# Changelog

Журнал рішень і змін по сесіях. Кожен запис — стисле резюме того, що обговорили і що реально задеплоїли.

## 2026-06-22

### Обговорили (логіка/продукт)

- **Проблема**: юзери "зливаються" — тренуються, але без бота, бот стає другорядним.
- **Реакції → HP**: тренування вже автоматично публікуються в груповий чат (`REPORTS_GROUP_ID`) з відео + текстовим репортом. Рішили: якщо тренування набирає **3+ будь-яких реакції**, автор отримує **+20 HP**, бот відповідає reply-повідомленням в групі. Дедлайн на нарахування — **до кінця доби** тренування за Києвом (не 48 годин), щоб реакції рахувались чесно, "по гарячому".
- **Стрік-фриз** (відкладено на пізніше): ідея — не тижнева механіка, а денна. Якщо юзер вже зробив 3+ тренування з початку тижня, а потім пропустив цілий день — замість автоматичного згорання стріку запропонувати заморозку (кнопка). Деталі (поведінка нижче порогу 3, час перевірки дня, економіка заморозок) ще не узгоджені — повернутись до цього окремо.
- **Календар у Mini App**: користувачу було недостатньо просто бачити кольорові дні — додали статистику місяця (скільки днів тренувався, скільки пропустив, розбивка по типах активності). Двічі редизайнили подачу: спершу текстовий рядок, потім — за фідбеком "наляписто" — плитки + сітка.

### Задеплоєно (код)

- **`reactions.py`** (новий файл) — обробник `message_reaction_count` на групу репортів: рахує сумарну кількість реакцій, перевіряє мета-дані тренування (`report_meta`), перевіряє дедлайн (`reaction_window`, діє до кінця доби Києва), нараховує +20 HP через `update_user_activity` (`action_name = "Reaction Bonus"`, ідемпотентно через `video_id = reaction_bonus:<message_id>` + Redis-лок), відповідає в групі: *"🔥 Суспільство одобрило твоє тренування! Нараховано +20 HP 💪"*.
- **`services.py`** — при публікації тренування в групу тепер додатково ставить маркер `KeyManager.get_reaction_window_key(message_id)` з TTL до кінця поточної доби (Київ) — окремо від 48-годинного `report_meta`, який далі обслуговує систему скарг/відкату і не зачеплений.
- **`cache.py`** — нові ключі: `get_reaction_bonus_lock_key`, `get_reaction_window_key`.
- **`database.py` / `tasks.py` / `handlers.py`** — `"Reaction Bonus"` додано в `REAL_ACTIVITY_ACTIONS` (рахується в `hp_total`, не рахується як тренування для стріку/ачівок — за аналогією з `"Welcome Bonus"`/`"Returned"`).
- **`supabase/reaction_bonus.sql`** — унікальний індекс `uq_activities_reaction_bonus_video_id` (захист від подвійного нарахування на рівні БД). Виконано користувачем у Supabase SQL Editor.
- **`supabase/webapp_analytics.sql`** — таблиця `webapp_events` для аналітики Mini App. Виконано користувачем у Supabase SQL Editor.
- **`docs/profile.html`** — на вкладці "Календар" під сіткою днів додано статистику поточного місяця:
  - 2 плитки: "✅ Тренувався — N днів" / "❌ Пропустив — N днів" (пропуск = взагалі жодного запису за день, Rest/Skip не рахуються як пропуск);
  - сітка з 5 комірок: Street / Gym / Rest / Skip / Challenge — кількість за місяць;
  - рахується повністю на фронті з даних, які вже приходять у `/api/profile`, без змін бекенду.
